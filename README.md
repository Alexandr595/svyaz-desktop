# Связь Desktop · 0.4.1

<img src="assets/svyaz.svg" width="88" alt="Иконка Связи" />

Приложение для Windows 10/11 x64: обработка DPI, локальный MTProxy для Telegram Desktop и выборочный системный прокси для обычного браузера. Discord подключается напрямую; для его UDP IP discovery добавлена отдельная стратегия zapret2. Приложение не создаёт VPN-туннель.

**[Скачать установщик для Windows x64](https://github.com/Alexandr595/svyaz-desktop/releases/download/v0.4.1/Svyaz-Setup-0.4.1-x64.exe)** · [Все выпуски](https://github.com/Alexandr595/svyaz-desktop/releases)

## Оформление и установка

В 0.4 добавлены собственная панель окна без белой системной полосы, скругления, иконка в семи размерах и переключатель «Стекло». На Windows 11 22621+ используется системный Desktop Acrylic; если прозрачность в Windows отключена или эффект недоступен, применяется непрозрачная тёмная тема. График, счётчики и длительность сеанса показывают реальные измерения.

Установщик включает .NET и ставит приложение для текущего пользователя в `%LOCALAPPDATA%\Programs\Svyaz`, создаёт ярлыки и запись удаления в Windows. Для самого сетевого движка права администратора запрашиваются позднее, при подключении. Автозапуск и служба не устанавливаются.

При переходе с переносимой версии можно выбрать её папку `data` на странице переноса настроек. Переносятся только `settings.json` и локальный секрет Telegram. Обновление установленной версии сохраняет существующие настройки. Удаление программы сохраняет `data` и пользовательские файлы. Установщик пока без цифровой подписи.

В 0.4.1 исправлена кодировка русского текста установщика, удаления и ярлыков. При обновлении удаляются ярлыки с испорченными именами, созданные установщиком 0.4.0.

## Обновления из приложения

«Связь» проверяет опубликованные GitHub Releases при запуске и раз в четыре часа. Когда доступна более новая версия, справа в шапке появляется кнопка «Доступно …». Во вкладке «Обновления» можно проверить вручную, отключить фоновую проверку или предварительные выпуски. Получение предварительных выпусков изначально включено: текущая серия 0.x ещё проходит проверку сетевых функций.

Нажатие кнопки скачивает установщик с прогрессом; повторное нажатие отменяет загрузку. До завершения загрузки соединения продолжают работать. Проверяются размер файла, SHA-256 из API GitHub и адреса загрузки: только этот репозиторий и HTTPS CDN GitHub. Повреждённые и незавершённые загрузки не запускаются. Проверка хеша не заменяет цифровую подпись издателя.

После проверки запускается установка в текущую папку, приложение останавливает свои соединения и закрывается. Установщик сохраняет настройки и открывает новую версию. Подключение затем включается вручную. Новая версия не устанавливается автоматически без нажатия кнопки. Загруженный установщик хранится в `%LOCALAPPDATA%\Svyaz\Updates`.

В 0.4.0 такого механизма ещё нет: один раз установите 0.4.1 вручную поверх неё. Затем последующие выпуски можно устанавливать из приложения. Если папка недоступна для записи или установку блокирует Windows, приложение покажет ошибку установки/загрузки; выпуски также доступны по ссылке GitHub. Ошибка фоновой проверки не останавливает сетевой движок.

## От чего зависит доступ

| Сервис | Текущий маршрут | Внешняя зависимость |
| --- | --- | --- |
| Discord, YouTube | Прямое подключение с обработкой zapret2 | Сеть и актуальность стратегии DPI |
| Telegram Desktop | Локальный MTProxy → официальный Telegram WSS | Настроенный внешний SOCKS5, если он включён |
| ChatGPT | Выборочный CONNECT → настроенный SOCKS5 либо напрямую | Доступность узла и решение самого сервиса о доступе |

Начальные SOCKS5 выбирались из [открытого списка monosans/proxy-list](https://github.com/monosans/proxy-list). Их операторы неизвестны. Автоматического обновления списка, SLA и гарантии срока работы нет: публичный узел может отключиться в любой момент. Можно указать собственный или доверенный SOCKS5. Программа не имеет даты истечения; прямые стратегии тоже могут потребовать обновления при изменениях фильтрации. В коде и сборке нет собственного облачного сервера разработчика.

## Что подтверждено

- Discord и YouTube: HTTPS 200 через физический Ethernet с профилем `z-fake-md5`; ранее в отдельном Edge проверено воспроизведение одного видео YouTube.
- Telegram: сквозной запрос MTProto через локальный MTProxy → официальный WebSocket дата-центра → корректный resPQ с проверкой nonce. Вход в аккаунт, сообщения и медиа этим тестом не проверяются.
- Discord: WebSocket Gateway вернул Hello через тот же локальный прокси. Это проверка транспорта; голос, микрофон, слышимость и демонстрация экрана требуют проверки в самом Discord.
- Системный PAC: настоящий Edge без явного флага прокси направил выбранный тестовый домен в локальный прокси; контрольный домен в него не попал. Прежние настройки Windows восстановились после теста.
- Авария: после принудительного завершения процесса-владельца отдельный наблюдатель восстановил прежние настройки Windows PAC.
- Наблюдался сеанс движка длительностью около 85 минут до остановки пользователем, без автоматического отката. Это не испытание длительного голосового соединения.

**Доступ ко всем функциям пока не подтверждён.** ChatGPT в HTTPS-проверке возвращает 403. Голос Discord и работа авторизованного Telegram Desktop должны быть подтверждены пользователем в клиентах. Четыре сети МТС / Планета / ИНСИС / Ростелеком отдельно не испытаны.

## Запуск и настольные приложения

1. Запустите установщик `Svyaz-Setup-0.4.1-x64.exe`. Для переносимого варианта распакуйте весь `Svyaz-0.4.1-win-x64.zip`; ему нужен [.NET 8 Desktop Runtime x64](https://dotnet.microsoft.com/en-us/download/dotnet/8.0). В установщик runtime уже включён.
2. Запустите `Svyaz.exe`. Выберите физический интерфейс, например Ethernet. «Маршрут Windows» использует системный маршрут, в том числе работающий VPN.
3. Нажмите «Подключить» и подтвердите запрос Windows на права администратора. Дождитесь запуска. Автоматически проверятся MTProto и Discord Gateway; статусы появятся на карточках.
4. **Telegram Desktop:** нажмите «Подключить Telegram» и подтвердите предложение прокси в Telegram. Добавляется локальный MTProxy `127.0.0.1:18081`. Старые прокси Telegram не удаляются. Он работает только пока запущена «Связь»; после остановки отключите этот узел в Telegram, чтобы вернуть прежний маршрут.
5. **Discord Desktop:** исключите Discord из действующего VPN, чтобы проверить прямой доступ. В Happ с режимом «Прокси только для выбранных приложений» для этого убирают Discord из списка. После смены маршрута обновите Discord (`Ctrl+R`) или полностью перезапустите его. Затем проверьте текст и голос в выбранном вами канале.
6. **Ваш браузер:** включённый в настройках системный PAC направляет выбранные сервисы в локальный CONNECT-прокси `127.0.0.1:18080`. Остальные адреса получают `DIRECT`, то есть используют обычную маршрутизацию Windows и правила вашего VPN. Браузер должен использовать системные настройки прокси. Его отдельный прокси или расширение могут переопределять их.
7. В «Настройках» замените примеры контрольных URL на критичные сервисы своей инфраструктуры. Они должны отвечать 2xx/3xx без входа в аккаунт и находиться вне списка обработки.

«Остановить» выключает собственный движок и локальные прокси и возвращает прежний системный PAC. Закрытие окна тоже останавливает работу. Приложение не устанавливает службу и автозапуск. Для длительной работы держите его открытым; свёрнутое окно продолжает сеанс.

## Как работает подключение

Исходящие IPv4 TCP-сокеты локальных прокси привязаны к выбранному интерфейсу. При исчезновении интерфейса приложение не переключается незаметно на другой. Имена для прямых соединений разрешает Windows; SOCKS5 передаёт имена внешнему узлу.

Telegram Desktop получает локальный MTProxy. Мост адаптирует внешний слой обфускации к документированному WSS-транспорту официальных дата-центров Telegram. Содержимое сообщений MTProto остаётся зашифрованным. Секрет локального узла создаётся в `data/telegram-local-secret.txt` и не включается в архив или отчёт.

Для исходящего WSS Telegram и ChatGPT можно отдельно настроить внешние SOCKS5. Начальные публичные узлы могут исчезнуть в любой момент; их операторы неизвестны. Для устойчивой работы используйте свой доступный узел. TLS-сертификаты проверяются обычным способом. Прокси с логином и паролем эта версия не поддерживает.

TLS-стратегия ограничена доменным списком, интерфейсом и TCP 443. UDP-стратегия ограничена сигнатурой Discord IP discovery и портами `19294–19344, 50000–65535`; обычный STUN, неизвестный UDP, DNS и QUIC не изменяются. Она не расшифровывает голос и не гарантирует доступность каждого голосового региона. Telegram-звонки отдельно не реализованы и не подтверждены.

## Восстановление и диагностика

- Системный прокси включается через WinINet. Значения URL, ProxyEnable и флаги подключения сохраняются в `data/desktop-proxy-backup.json`. При остановке они восстанавливаются; отдельный наблюдатель делает это и при аварийном завершении. Изменения другого приложения не перезаписываются.
- Если в Windows уже включён другой системный прокси/PAC, приложение откажется его заменять. Отключите его в соответствующем приложении; TUN можно оставить.
- «Проверить MTProto и Gateway» не использует логины, токены аккаунтов, сообщения, присоединение к каналам и микрофон. Результат записывается в `data/native-probes.json`.
- HTTP 403 означает ответ сервера, а не подтверждённый доступ. Даже успешный HTTP/Gateway не подтверждает все функции клиента.
- Два сбоя контрольного адреса подряд останавливают движок. Ошибка внешнего прокси Telegram или ChatGPT не останавливает обработку остальных сервисов. После ошибки движка локальные маршруты остаются включены до явной остановки.
- Настройки: `data/settings.json`; журнал: `data/session.log`; последнее состояние: `data/status.json`. Журнал ротируется. Телеметрии нет.
- При аварии движок завершается через Windows Job Object. Между проверками остаётся окно обнаружения сбоя: интервал плюс срок запроса.

У подключений нет установленного лимита времени. Их фактическая длительность зависит от сети, фильтрации, серверов и внешних прокси. Измеренные 85 минут не позволяют обещать непрерывную работу неделями.

## Сборка и проверки

```powershell
dotnet build src/Svyaz.App/Svyaz.App.csproj -c Release
dotnet run --project tests/Svyaz.Checks/Svyaz.Checks.csproj -c Release
.\build.ps1
.\installer\build-installer.ps1
.\installer\smoke-test.ps1
```

Для свежего checkout сначала выполните `./tools/fetch-engines.ps1` и `dotnet run --project tools/Svyaz.AssetBuilder/Svyaz.AssetBuilder.csproj -c Release`. Бинарные файлы сторонних движков не хранятся в Git; скрипт скачивает закреплённые официальные архивы и проверяет SHA-256. Lua, лицензии, образцы пакетов и исходник векторной иконки включены в репозиторий. Компилятор NSIS тоже загружается из официального дистрибутива с проверкой хеша; код установщика — `installer/Svyaz.nsi`.

56 локальных проверок: TCP/SOCKS5, TLS, отмена и завершение процессов, политика остановки, PAC и владение настройками, AES-CTR по вектору NIST; выбор новых выпусков, каналы обновлений, SHA-256, перенаправления, повреждение и отмена загрузки. Дополнительно выполнены реальные проверки системного PAC в Edge, аварийного наблюдателя, MTProto/WSS и Discord Gateway. Smoke-тест установщика проверяет русский текст в метаданных, установку в папку с пробелами и кириллицей, автономный запуск, импорт, режим обновления, удаление и сохранение пользовательских данных. Параметр `-PreviousInstaller` позволяет проверить переход с прежнего установщика.

Дополнительные команды проверок: `--native-client-check <settings.json>`, `--telegram-bridge-check <settings.json>`, `--desktop-proxy-smoke`, `--proxy-watch-smoke <Svyaz.exe>`. Последние две временно проверяют системный PAC только на доменах `.invalid` и восстанавливают прежние значения.
