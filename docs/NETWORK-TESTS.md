# Проверка в сетях провайдеров

Все четыре сети в таблице пока **не проверены отдельно**. Название провайдера в настройках — метка отчёта, не готовый профиль. Внутри одного провайдера результат может зависеть от региона, мобильной/фиксированной сети, IPv4/IPv6 и оборудования.

В текущем подключении (провайдер не установлен) 2 ноября 2026 проверены GoodbyeDPI и zapret2 1.0.6. Прежние два профиля GoodbyeDPI не помогли. Профиль zapret2 `z-fake-md5` восстановил HTTPS Discord и YouTube. В отдельном Edge через локальный прокси открылись Telegram Web и Discord, у YouTube воспроизводилось одно короткое видео. Telegram использовал разрешённый внешний SOCKS5. ChatGPT напрямую отвечал 403; с внешними узлами получены 403 или проверка Cloudflare. Функции аккаунтов и нативных клиентов не проверены.

После сообщения пользователя о неработоспособности обнаружено, что движок и локальный прокси выключены; причина предыдущей остановки не была сохранена. В 0.2.1 исправлена возможная общая остановка из-за внешнего прокси, добавлен постоянный журнал. Последующие результаты сеансов приведены ниже.

Обновление 0.3.0: запуск 2 ноября 23:16 — остановка пользователем 3 ноября 00:41, около 85 минут без автоматического отката движка. Это мониторинг контрольных HTTPS-адресов, а не длительное испытание голоса. 4 ноября повторно получены корректный MTProto resPQ через локальный MTProxy/WSS и Discord Gateway Hello. Настоящий Telegram Desktop установил TCP-соединения с локальным MTProxy. Работа чатов и медиа ожидает подтверждения пользователя. Голосовой канал пока не проверен.

1. Выберите нужное подключение и укажите название сети. Если VPN остаётся включённым, выберите физический интерфейс и пользуйтесь только отдельным браузером приложения. Это проверка привязанных TCP-соединений при активном туннеле; отдельную проверку при выключенном VPN следует записать отдельно. Сохраните 2–3 контрольных URL своих критичных сервисов, которые отвечают без авторизации. Внутренние HTTPS-адреса тоже допустимы, если их сертификат доверен системе.
2. Выполните проверку с выключенной обработкой, экспортируйте отчёт.
3. Включите профиль `zapret2 · fake MD5`, подтвердите UAC. В отдельном браузере повторите сценарии ниже. Экспортируйте отчёт и отдельно запишите наблюдаемое поведение, какие сервисы шли через внешние прокси.
4. Остановите обработку, при необходимости проверьте другой профиль тем же способом. После теста вернитесь к выключенной обработке и проверьте контрольные сервисы снова.
5. Запишите дату, регион, тип подключения, версии Windows и браузера. Не публикуйте отчёты с внутренними адресами без проверки содержимого.

| Сервис | Проверка в приложении | Что не следует выводить из HTTP 200 |
| --- | --- | --- |
| ChatGPT | Вход, новая беседа, потоковый ответ, загрузка и открытие файла | Успех главной страницы не подтверждает API, файлы и голос |
| Telegram Web | Вход, текст, медиа, повторное соединение | Не подтверждает Telegram Desktop, MTProto и звонки |
| Discord | Вход, текст, вложение, повторное соединение | Не подтверждает голос и видео через UDP |
| YouTube | Страница видео, воспроизведение, смена качества, перемотка | Не подтверждает доступность медиапотока и его скорость |

Автоостановка срабатывает после двух последовательных провалов контрольного URL. Это может означать внешний сбой; дополнительно проверьте сервис после остановки. Нельзя использовать искусственное отключение критичного производственного сервиса ради теста — логика регрессии уже покрыта локальными проверками с подставными результатами.
